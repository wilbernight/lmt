# دفتر (Daftar)

سامانه مدیریت کار تیمی، الهام‌گرفته از میزیتو، روی **Laravel 12 + Inertia + Vue 3 + Tailwind 4**.
راست‌به‌چپ، فارسی، تقویم شمسی، حالت تاریک/روشن.

### اشخاص بدون اکانت

هر جای برنامه که اسم یک همکار لازم شود — مسئول وظیفه، گیرنده نامه، شرکت‌کننده جلسه — می‌توان نام را **آزاد تایپ کرد**. نام‌های تکراری با نرمال‌سازی حروف فارسی (ي/ی، ك/ک، نیم‌فاصله، ارقام فارسی/لاتین) به همان شخص برمی‌گردند و نام جدید یک بار در دایرکتوری میزکار (`people`) ذخیره می‌شود تا دفعه بعد قابل انتخاب باشد. این اشخاص اکانت ندارند، لاگین نمی‌کنند و فقط اسم و آواتار حرفیِ خط‌چین‌دارشان دیده می‌شود؛ داده‌هایشان مثل بقیه رمزنگاری‌شده است.

## ساعت کار و حضور و غیاب

- **زمان‌سنج روی هر وظیفه:** دکمه «شروع کار» در پنجره وظیفه؛ هر نفر فقط یک زمان‌سنج فعال دارد (شروع وظیفه دیگر، قبلی را متوقف می‌کند). زمان‌سنج فعال در نوار بالا با زمان زنده دیده می‌شود و از همان‌جا متوقف می‌شود. ثبت دستی زمان، تخمین زمان و مقایسه با زمان واقعی هم هست.
- **ساعت کار پروژه:** نمای «ساعت کار» در هر پروژه، جمع کل، به تفکیک افراد و وظیفه، نمودار ۳۰ روز، فیلتر بازه تاریخ، و اینکه الان چه کسی روی چه کاری است.
- **حضور پرسنل:** ورود به پنل = ثبت ورود، «خروج» = ثبت خروج (و توقف زمان‌سنج). اگر کسی بدون خروج مرورگر را ببندد، پس از مدت عدم فعالیت (`SESSION_LIFETIME` دقیقه) خروجش در زمان آخرین فعالیت ثبت می‌شود. صفحه «حضور و ساعت کار»: جدول روزانه برای همه پرسنل (مدیران میزکار)، فهرست ورود و خروج با IP، مقایسه حضور با کار ثبت‌شده، خروجی اکسل. اعضای عادی فقط ساعت‌های خودشان را می‌بینند.

برای بستن خودکار حضورهای رهاشده، زمان‌بند لاراول باید اجرا شود:

```bash
php artisan schedule:work
```

(در سرور: یک cron هر دقیقه `php artisan schedule:run`)

## پنل مدیریت سایت (`/admin`)

- **کاربران:** جستجو و فیلتر، مسدود کردن با دلیل (خروج فوری از همه دستگاه‌ها و جلوگیری از ورود)، رفع مسدودی، دسترسی مدیر سایت، اجازه یا منع ساخت میزکار، سقف تعداد میزکار، فضای هر میزکار (با امکان اعمال روی میزکارهای فعلی)، خروج اجباری، بازنشانی 2FA، تأیید دستی ایمیل، رخدادهای کاربر
- **میزکارها:** تغییر فضا، غیرفعال‌سازی (اعضا دسترسی ندارند ولی داده حذف نمی‌شود)، فیلتر «نزدیک به پر شدن»
- **تنظیمات سایت:** باز یا بسته بودن ثبت‌نام، فضای پیش‌فرض، سقف پیش‌فرض میزکار، حداکثر حجم فایل

پنل برای غیرمدیران «پیدا نشد» برمی‌گرداند، دوباره رمز می‌پرسد و در production ورود دومرحله‌ای را الزامی می‌کند (`ADMIN_REQUIRES_2FA`). مدیر نمی‌تواند خودش را مسدود یا از مدیریت خارج کند و سایت همیشه حداقل یک مدیر دارد. همه اقدامات مدیر در گزارش رخدادها ثبت می‌شود.

اولین مدیر را فقط از روی سرور می‌شود ساخت:

```bash
php artisan app:admin you@example.com
```

## رمزنگاری اطلاعات در پایگاه داده

متن همه بخش‌ها داخل دیتابیس با **AES-256-GCM** (رمزنگاری احرازشده؛ دستکاری داده باعث خطا می‌شود، نه داده خراب) رمز می‌شود: نام و توضیح پروژه‌ها و ستون‌ها، عنوان و توضیح وظایف، چک‌لیست‌ها، گزارش‌ها، تاریخچه، یادداشت زمان‌ها، همه اطلاعات مشتریان (نام، تلفن، ایمیل، نشانی، ارزش معامله...)، سوابق تماس، موضوع و متن نامه‌ها و دستور پاراف، پیام‌های گفتگو و نام گروه‌ها، یادداشت‌ها، نام برچسب‌ها و دسته‌بندی‌ها و میزکارها، **نام اشخاص خارجی، موضوع/شرح صورت‌جلسه‌ها و عنوان اقدامات**، نام فایل‌ها، اعلان‌ها، جزئیات گزارش رخدادها، متن پیامک‌ها، نام گروه‌های پیامک و شماره تماس کاربران. **خود فایل‌های پیوست و تصاویر پروفایل** هم روی دیسک رمز می‌شوند.

- کلید جدا از `APP_KEY` است: `DATA_ENCRYPTION_KEY` در `.env` (هرگز داخل دیتابیس نیست). کسی که فقط به دیتابیس یا بکاپ آن دسترسی پیدا کند (SQL injection، بکاپ لو رفته، نفوذ به سرور دیتابیس) فقط متن تصادفی می‌بیند.
- هر مقدار با nonce تصادفی رمز می‌شود؛ دو متن یکسان در دیتابیس متفاوت دیده می‌شوند.
- جستجو و مرتب‌سازی پس از رمزگشایی در خود برنامه انجام می‌شود.
- **از کلید پشتیبان بگیرید** (جدا از بکاپ دیتابیس). بدون آن اطلاعات قابل بازیابی نیست.
- چرخش کلید: کلید قبلی را در `DATA_ENCRYPTION_PREVIOUS_KEYS` بگذارید، کلید جدید بسازید و `php artisan app:reencrypt` را اجرا کنید.
- به‌صورت آگاهانه رمز نشده: شناسه‌ها، تاریخ‌ها، وضعیت‌ها (برای فیلتر)، نام و ایمیل کاربران و ایمیل دعوت‌نامه‌ها (برای ورود و جستجوی حساب).
- محدودیت: اگر کل سرور (دیتابیس **و** فایل `.env`) به دست مهاجم بیفتد، چون خود برنامه باید بتواند داده‌ها را بخواند، رمزنگاری سمت برنامه جلوی او را نمی‌گیرد؛ برای آن سطح، کلید را در یک سرویس مدیریت کلید (KMS/HSM) نگه دارید.

## امنیت

- **احراز هویت:** Fortify؛ ورود دومرحله‌ای (TOTP + کدهای بازیابی)، تأیید ایمیل، تأیید دوباره رمز برای بخش‌های حساس، سیاست رمز قوی (در production با بررسی رمزهای لو رفته).
- **محدودیت نرخ:** ورود (به ازای حساب+IP و به ازای IP)، 2FA، ثبت‌نام، بازیابی رمز، آپلود، پیام، دعوت، جستجو و همه درخواست‌ها.
- **عدم افشای حساب‌ها:** پاسخ بازیابی رمز برای ایمیل موجود و ناموجود یکسان است؛ میزکار برای غیرعضو «پیدا نشد» (۴۰۴) برمی‌گرداند.
- **کنترل دسترسی:** Policy برای هر مدل، اتصال تودرتوی مسیرها (scoped bindings) جلوی IDOR بین میزکارها را می‌گیرد، شناسه‌ها ULID هستند (قابل حدس نیستند)، فیلدهای حساس فقط سمت سرور مقدار می‌گیرند (mass assignment بسته است).
- **هدرها:** CSP سخت‌گیرانه با nonce (بدون `unsafe-inline` برای اسکریپت)، `X-Frame-Options: DENY`، `nosniff`، `Referrer-Policy`، `Permissions-Policy`، COOP/CORP و HSTS روی HTTPS.
- **فایل‌ها:** خارج از پوشه عمومی با نام تصادفی ذخیره می‌شوند، نوع فایل از محتوای آن تشخیص داده می‌شود (نه پسوند)، SVG/HTML/PHP رد می‌شوند، دانلود فقط بعد از بررسی دسترسی و با `Content-Disposition: attachment`.
- **XSS:** همه محتوای کاربر به‌صورت متن ساده نمایش داده می‌شود (بدون `v-html`)، لینک‌های وب‌سایت فقط http/https.
- **نشست:** رمزنگاری‌شده، HttpOnly، SameSite، مشاهده نشست‌های فعال و خروج از سایر دستگاه‌ها.
- **ثبت رخداد:** ورود، ورود ناموفق، قفل، تغییر نقش، حذف و خروجی گرفتن در `audit_logs` با IP ثبت می‌شود.
- **CSV:** در خروجی مشتریان جلوی Formula Injection گرفته شده است.
- **پایگاه داده:** کاربر جداگانه با دسترسی محدود به همین دیتابیس (نه root).

## اجرا (محلی)

پیش‌نیاز: PHP 8.2+، Composer، Node 20+، MariaDB/MySQL.

```bash
composer install
npm install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed
npm run build
php artisan serve
```

برای گفتگو و برد زنده، در ترمینال دیگری:

```bash
php artisan reverb:start --port=8081
```

حساب‌های نمایشی را seeder می‌سازد (`database/seeders/DatabaseSeeder.php`)؛ رمز همه از `DEMO_PASSWORD` در `.env` خوانده می‌شود. این seeder در production اجرا نمی‌شود.

## تست‌ها

```bash
php artisan test
```

تست‌ها روی پایگاه داده `daftar_test` اجرا می‌شوند و شامل تست‌های امنیتی (IDOR، دسترسی‌ها، آپلود فایل، هدرها، محدودیت نرخ، عدم افشای حساب) هستند.

## چک‌لیست انتشار (production)

- `APP_ENV=production`، `APP_DEBUG=false`، یک `APP_KEY` جدید
- فقط HTTPS؛ `SESSION_SECURE_COOKIE=true` و `REVERB_SCHEME=https`
- رمزهای جدید و قوی برای دیتابیس و Reverb؛ `TRUSTED_PROXIES` اگر پشت پروکسی هستید
- `MAIL_*` واقعی برای ارسال تأیید ایمیل و دعوت‌نامه
- `php artisan config:cache route:cache view:cache` و `npm run build`
- `QUEUE_CONNECTION=database` و اجرای `php artisan queue:work` به‌عنوان سرویس
- فقط پوشه `public` در دسترس وب‌سرور باشد
- پشتیبان‌گیری منظم از دیتابیس و `storage/app/private`
